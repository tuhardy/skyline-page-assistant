# SKYLINE 真实页面助手

方案一的全局页面助手：在真实 SKYLINE GoIP 主页面旁提供功能导航，并在 IMEI 页面提供分步指导、单个/批量变更预览、确认后代操作和提交后回读。

## 当前范围

- 当前版本 **0.6.0**，适配 `main_en.html` / `main_cn.html` 全局导航、`goip_imei_en.html` / `goip_imei_cn.html` 操作，以及 `user_management_en.html` / `user_management_cn.html` 的 ETMS 注册指导/确认后代操作。英文 IMEI DOM 来自下载的真实页面；ETMS 设备网管表单已按真实英文页样本核对，中文完整流程和真实 Submit 仍需实机验收。
- 控制器驻留顶层 `main_en.html` / `main_cn.html`，通过同源框架读取右侧真实 IMEI 或 ETMS 页面；不再把浮动面板限制在狭窄的功能框架内。
- 非 IMEI/ETMS 页面也显示全局功能列表。内置 IMEI、独立 ETMS 注册、EIMS 设置、SMS 控制、四类语音控制和 Save/Reboot 共 9 个入口；IMEI 与 ETMS 提供确认后代操作，其余仅导航，Save/Reboot 仅定位。
- 设备中间内容宽度为 1050px。宽屏下，面板位于顶层浏览器右侧空白区；窗口太窄时仍可能需要收起面板，避免遮挡。
- 也支持直接打开 IMEI 功能页。嵌套 IMEI 框架不重复注入控制器。
- 支持 IP、域名和自定义端口，不固定设备地址，但最终仍会核对真实 URL 和 DOM 特征。
- 仅处理“指定 IMEI 前缀”模式下的端口 IMEI 表单，不擅自切换其他模式。
- 不调用猜测的配置 API，不提供 ETMS 取号、SMS、语音或自动保存/重启的代操作。

## 安装和刷新

1. 在 Chrome 或 Edge 的扩展管理页开启“开发人员模式”。
2. 选择“加载解压缩的扩展”，加载本目录。
3. 更新代码后，先在扩展管理页点击本扩展的“重新加载”。
4. **再刷新设备顶层主页面**（通常是 `main_en.html`），不能只刷新右侧 IMEI 框架；旧顶层文档不会自动获得新控制器。
5. 登录真实设备，从设备菜单进入 **IMEI Settings**。点击扩展工具栏图标可重新打开被关闭的面板。

## 全局功能导航

- 打开设备顶层主页面后，无论右侧当前是什么页面，面板都保留并显示功能列表。
- 点击 **IMEI 修改** 会展开并调用左侧真实菜单链接；右侧返回后，必须同时匹配真实 URL 和 IMEI DOM 才进入工作区。
- **ETMS 注册** 独立指向 `user_management_en.html` / `user_management_cn.html`，进入真实设备网管区块后提供分步指导、非密码字段预览、明确确认、真实 Submit 和状态 OK 回读；助手不打开外部账号注册链接，也不读取或保存 ETMS 密码。**EIMS 设置、SMS 控制、通话时长、呼叫次数、通话号码、呼叫控制** 当前仅打开真实页面，不读取敏感配置，也不提供修改按钮。ETMS 不会与 EIMS 混并。
- **保存 / 重启** 只展开并定位真实菜单，不自动导航、保存或重启。
- 未提交预览存在时，助手会阻止通过功能列表离开，避免丢失取消恢复入口。已尝试 Submit 后允许切换页面，待回读记录仍保留；回到原 IMEI 页面后继续核对。
- 直接打开 IMEI 功能页时仍使用原有单页工作区，不显示无真实菜单可用的全局导航。

## 设备类型与功能包

- **自动**：优先读取顶层右上角型号文字，`MP` / `MOIP` 识别为短信设备，`GoIP` / `GP` 识别为语音设备；`GoIP16/512` 中的 `16` 是端口数，不按 `512` 误判。右上角不可用时，最多发起两次同源只读状态查询（状态页和必要时的数据端点），`5` 开头识别为语音、`6` 开头识别为短信；仍不可用时才参考左侧真实菜单证据。
- 折叠的父菜单不等于功能不可用，菜单兜底识别不会因菜单默认收起而漏判。标记为 `MenuOff` 或隐藏的入口不作为可用证据，也不会因手动切换而被强制点击。
- **短信功能包**：通用入口和 ETMS/EIMS/SMS，不显示语音控制；**语音功能包**：通用入口、短信入口和四类语音导航，共 9 个入口；**未识别**：放开全部入口，点击时仍按真实菜单可用性校验并提示。
- 面板提供 **自动 / 短信 / 语音** 手动切换，手动选择优先于自动结果，用于纠正误判。每个设备来源仅持久保存这一项偏好，切回“自动”会重新按右上角和软件版本识别。
- 功能包只控制助手显示哪些入口；真实菜单不可用时会明确报告未导航，不会把手动切换当成绕过设备权限的方式。

## ETMS 注册

1. 从功能列表进入 **ETMS 注册**；助手只调用真实左侧菜单打开 `user_management_en.html` / `user_management_cn.html`，并定位“设备网管 / Network Management System”区块。
2. 直接在右侧真实表单中选择 **ETMS** 网管类型（`NONE` / `ERMS` 不属于本流程），并填写服务器 IP/域名、网管端口、账号和密码。注册常需多次尝试：设备会在真实表单中保留已保存的内容，多次尝试无需重复填写；助手不提供自己的表单，也不代填任何字段。
3. 若没有 ETMS 账号，请先在服务商处注册；助手不会自动打开页面里的外部注册链接。
4. 点击“读取真实表单并预览”：助手只读取真实表单的非密码字段并校验（类型必须是 ETMS、服务器/端口/账号合法、真实密码框非空），生成预览前不改动真实页面。密码完全不进入扩展——只检查是否已填写，不读取、不显示、不保存，预览中仅显示“已填写”。
5. 核对预览的非密码字段后，单独点击“确认并提交 ETMS 注册”，助手才会点击该区块原有的真实 `Submit / 确定`；点击前会再次核对真实表单与预览一致、类型仍为 ETMS 且密码框仍非空，否则停止。
6. 提交后等待真实状态字段回读为 `OK`。回读只核对 ETMS 类型、服务器、端口、账号和状态；密码不由助手回读。若状态长时间不是 `OK`，会如实显示未确认，而不是把点击按钮当作注册成功。
7. 设备页面自身会异步刷新状态字段；ETMS 工作区激活期间每秒同步一次该状态（只更新显示，不改动表单和预览）。注册成功后离开再回来，工作区也会显示最新真实状态，不会停留在附加瞬间的空值。

## 单个修改

1. **模式**：核对真实页面为“指定 IMEI 前缀”。
2. **端口/IMEI**：选择真实页面已有的端口和槽位，输入完整的 14 或 15 位 IMEI；高亮控件旁会显示“第几步、在这里做什么”。
3. **提交回读**：预览原值和新值，确认后扩展填写真实输入框并点击设备原有 `Submit`。14 位 IMEI 的第 15 位由设备原提交脚本追加。
4. **保存重启**：只定位真实 `Save and Reboot` 菜单并提示影响，不自动点击或重启。

## 批量修改

1. 选择“批量修改”，设置 **起始端口、结束端口、每端口数量**，再输入 **8 位数字前缀**。面板实时显示类似“端口 2–4 · 每端口 8 个 · 共 24 个”的目标范围。
2. 选择处理方式：
   - **仅填空白**：保留所选范围内已有的非空值。
   - **清空所选范围后重建**：明确选择后，先调用设备真实 `Clear`。
3. 点击“生成批量预览”。扩展先核对每个目标端口/槽位真实存在且可编辑，再调用真实 `Copy` 和 `AutoComplete`，最后在 `finally` 中恢复所有输入框原来的禁用状态。“清空后重建”只启用所选范围；“仅填空白”只启用其中的空白槽位，已有非空值不会参与 Copy 或 Auto Complete。若检测到本次目标之外的输入变化，会停止预览。
4. 按钮通过设备原 `copyImei()`、`clearImei()`、`completeImeis()` 处理函数定位，不依赖“Copy”或“复制”等翻译文字。真实 `Copy` 不覆盖已有非空值，但遇到后续非空值时，会把它作为之后空白框的来源；保留非空值时，不同区段可能生成不同前缀，应以差异预览为准。
5. 预览分别显示 **目标数量** 和 **实际变更数量**，并列出每个变更端口/槽位的原值、新值。“仅填空白”的目标数是范围内的空白槽位数；没有空白时会停止且不修改任何值。Auto Complete 只改变当前页面输入框，尚未保存设备；未尝试 Submit 前可点击“取消并恢复”。
6. 核对后单独点击确认，才调用真实 `Submit`。预览生成后，前缀、处理方式和范围控件会锁定；任何输入框数量、名称或值再变化，执行都会停止。
7. 一旦尝试过真实 Submit，取消按钮不会恢复快照，也不会宣称“未提交”；只能等待回读或人工核对。

设备 Submit 会提交整张 IMEI 表，而不是只提交助手选定的范围。范围限制只约束助手调用真实准备按钮时修改哪些输入框；页面原有其他未保存编辑也会随 Submit 一起提交，操作前必须人工核对。

## 结果和延迟

- **成功**：提交后页面重新加载，所有待确认输入框的真实回读值与预览一致。
- **失败**：有限重试后仍有值不一致，或执行前检查发现模式、目标、快照已经变化。
- **无法确认**：回读控件缺失、页面没有完成返回、记录过期，或后台记录无法处理。

提交后如值尚未一致，会在 2.5 秒和 5 秒后最多进行 **2 次真实功能页刷新重读**。重试期间显示“尚未一致/正在重试”，不会立即把设备延迟当作最终失败；重试后仍不一致则如实报告。

“点击了按钮”本身从不被当作保存成功。

## 隐私和权限

- 内容脚本只匹配 `main_en.html` / `main_cn.html` 和 IMEI 功能页，并再次检查真实 DOM 特征。
- 不读取或保存设备登录密码；ETMS 密码完全不进入扩展——用户直接在真实表单填写，助手只检查真实密码框是否非空，不读取、不显示、不保存，也不由助手回读。
- 不发送设备配置到外部服务；除设备同源页面和必要的只读软件版本兜底查询外，没有外部网络请求代码，也不远程加载代码。
- `storage` 权限用于当前浏览器会话中的待回读记录，以及按设备来源保存的 `auto` / `sms` / `voice` 类型偏好。IMEI 待回读记录包含单个或批量目标、原值、预期值和重试次数；ETMS 待回读记录只包含类型、服务器、端口、账号、状态和重试次数，不包含密码。关闭浏览器后清除。
- 类型偏好不保存设备型号、菜单内容、账号、密码或任何配置；后台仅从真实消息发送者 URL 取得来源，不接受内容脚本指定其他来源。
- `chrome.storage.session` 和类型偏好分别由后台以固定键名的消息代理访问，不向内容脚本开放任意存储键。

## 文件结构

- `core/imei.js`：真实字段解析、IMEI 校验、批量差异和回读判断。
- `core/etms.js`：ETMS 设备网管表单识别、非密码快照、注册计划校验和状态 OK 回读判断；字段按 ID 或 `name` 双模式匹配，兼容省略输入框 id 的固件；密码只以“是否非空”的布尔参与校验，内容不进入扩展。
- `core/modules.js`：9 个内置模块、`common` / `sms` / `voice` 功能族、真实页面文件名和精确菜单链接规则；IMEI 与 ETMS 标记为可代操作。
- `core/device-profile.js`：右上角型号、软件版本和真实菜单证据的分级识别，手动偏好规范化和功能包过滤。
- `content/panel.js`：Shadow DOM 顶层浮动面板、设备类型切换、全局功能列表、IMEI 步骤和预览状态、ETMS 注册步骤和预览状态。
- `content/controller.js`：同源框架发现、自动识别与偏好同步、步骤标签、真实按钮、快照、提交和有限重读；ETMS 只核对真实表单并代点真实 Submit，不代填任何字段。
- `background.js`：扩展图标、IMEI/ETMS 待回读记录和按来源设备类型偏好代理。
- `tests/imei.test.js`：IMEI 与批量核心逻辑测试。
- `tests/etms.test.js`：ETMS 表单识别、字段校验、非密码快照和状态回读测试。
- `tests/modules.test.js`：模块能力、真实页面匹配和中英文菜单定位测试。
- `tests/device-profile.test.js`：右上角型号、软件版本、菜单兜底、折叠菜单、未知放开和手动覆盖测试。
- `tests/background.test.js`：待回读记录与固定键设备类型偏好代理测试。
- `IMPLEMENTATION-PLAN.md`：当前迭代及后续全局模块计划。
